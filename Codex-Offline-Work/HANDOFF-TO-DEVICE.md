# 离线成果交接与真实设备门槛

本轮完成的是 SM-T733 的可重复云端构建、候选内容校验及适配风险调查。没有连接真实设备，没有 ADB/USB 通信、刷写、解锁、分区或真实磁盘写入，离线准备阶段没有外部发布；后续正式交付仅授权独立分支推送、面向 main 的 PR 和构建包交付，不授权合并或设备操作。候选文件不能被称为“可安全刷入”。

## 下一步用户亲自完成的第一件事

**先完成重要资料备份，并在平板界面只读核对机型、固件及 OEM 解锁选项的可用性，记录状态；不切换开关、不确认解锁、不刷写。**

目的：再次确认设备确为 SM-T733 Wi-Fi 6GB/128GB、CHN T733ZCS9DYE1、Bootloader rev 9，并弄清是否存在厂商允许的解锁路径。设置页面中的选项存在不等于启动链已经解锁；地区、KG/RMM、账户或管理策略可能影响资格。只读查看应不改变系统；真正解锁可能清除数据、改变 Knox/安全功能且可能不可逆，需独立确认后再决定。本任务没有替用户接受此风险。

在 locked 状态，不尝试执行未经 Samsung 授权的候选启动镜像，不利用漏洞或绕过验证。若缺少合法 OEM 路径，则后续部署在此停止；SB 版本不能解决该限制。

## 在任何设备修改决定前补齐的材料

1. 来自可信来源、精确匹配 CHN rev 9 的完整原厂固件和恢复方案；对 BOOT、VENDOR_BOOT、DTBO、VBMETA 及 PIT 保存文件和哈希。用户电脑上的历史目录尚未转移到云端，不能认为这些材料已经存在。
2. 确定当前分区身份与容量。历史 `sda19/20/21/22` 只保留为线索，不据此生成写入命令。
3. 获得真实设备的启动状态、RAM 分区表/UEFI 内存图、加载地址和可恢复的诊断途径。这些是验证 BootShim 源/目的区间、cache/EL 条件、完整 6GB 路径的前提。
4. 合法 Windows 11 ARM64 安装介质及适用许可；先用只读工具核对架构、WIM 索引和哈希，再结合驱动信任链及 ACPI ID 确定版本。完整 DISM/BCDBoot 验证需 Windows/WinPE 主机和已明确的离线镜像目标。

收到原厂文件或实际 Windows 介质后，仍可先在云端继续比较和只读校验；这些材料尚未获得并不是要求立即刷写平板。

## 后续硬件验收顺序

只有用户另行授权设备阶段、确认可恢复及备份后，才制定准确的设备专用操作。先证明候选 UEFI 能获得执行，再核对屏幕/串口日志、UEFI 内存图和全部 RAM、UFS 只读枚举、USB、按键/输入与 ACPI，之后才评估 Windows Boot Manager。不得从结构校验直接跳到安装 Windows。

Windows 阶段需分别记录：系统版本及启动方式、可见物理内存与保留区域、UFS 稳定性、USB、显示、触摸/S Pen、Wi-Fi/蓝牙、音频、充电/电池、休眠/关机、温度和设备管理器错误。维护者 README 的“working”状态不能代替此台 6GB CHN 设备的记录。
